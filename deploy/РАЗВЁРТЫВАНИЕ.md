# Развёртывание сайта на хостинге Руцентра

Состояние на 11 августа 2026.

---

## Что где лежит

| | |
|---|---|
| Домен | `nlevel.pro`, зарегистрирован 11.08.2026 на год, NS `ns3/ns4/ns8.nic.ru` |
| Хостинг | Руцентр, тариф **«Сайт 1»**, оплачен до 11.09.2026 |
| Корень сайта | `/home/<логин>/nlevel.pro/docs` |
| FTP | `ftp.<логин>.nichost.ru`, отдельный пользователь с доступом только к корню сайта |
| Технический адрес | `<логин>.nichost.ru` — по нему сайт виден до делегирования домена |
| Сейчас развёрнуто | **статическая версия**, без админки |

**Репозиторий публичный.** Ни паролей, ни номеров договора, ни логинов
услуги здесь быть не должно — их видно всему интернету, а логин к FTP это
половина того, что нужно для перебора. Реквизиты смотрите в личном кабинете
Руцентра. Логин услуги виден в правом верхнем углу панели управления
хостингом, номер договора — в шапке личного кабинета.

FTP-пароль сбрасывается в панели: *FTP → пользователь → Сбросить пароль*.

## Главное ограничение

На тарифе «Сайт 1» **нет PHP** — это граница тарифа, а не настройка.
В панели: *Управление веб-сервером → Управление модулем PHP* → «Модуль PHP
не доступен для вашего тарифа». PHP появляется начиная с «Сайта 2».

Поэтому сейчас развёрнут статический слепок. Для посетителя он неотличим
от полной версии: все 18 страниц, прайс, галерея, отзывы с Яндекс.Карт,
кнопка записи. Не работает только админка — контент правится пересборкой.

## Сценарий А. Обновить статическую версию (тариф «Сайт 1»)

Пока сайт на «Сайте 1», любая правка контента идёт так:

```bash
# 1. Поправить data/content.json (или шаблоны)
# 2. Пересобрать под боевой домен
OUT=build-nlevel.pro SITE_URL=https://nlevel.pro ./export-static.sh
# 3. Залить содержимое build-nlevel.pro в корень сайта по FTP
```

Заливать нужно **содержимое** папки, а не саму папку: `index.html` должен
оказаться по пути `nlevel.pro/docs/index.html`. Имя `docs` тут совпадает
с нашей папкой для GitHub Pages — это разные вещи, легко перепутать.

## Сценарий Б. Перейти на PHP с админкой (тариф «Сайт 2» и выше)

### 1. Сменить тариф

Личный кабинет → *Активные услуги → Виртуальный хостинг* → столбец
**Параметры** → **Изменить тариф**. Дата окончания услуги не сдвигается,
оплачивается только разница за остаток дней. Нужны деньги на счёте договора.
Переключение — в течение часа.

### 2. Включить PHP для сайта

*Сайты → nlevel.pro → Настройки → Веб-сервер → Общие настройки → Версия PHP* —
выбрать 8.1 или новее.

### 3. Проверить расширения

Нужны **GD** (обработка загружаемых фотографий) и **fileinfo** (проверка,
что загружают картинку, а не скрипт). Без них админка сохранит текст,
но упадёт на загрузке изображения.

### 4. Залить PHP-версию

В корень сайта идёт весь репозиторий, **кроме**:

```
docs/            статика для GitHub Pages
build-*/         сборки под домен
research/        рабочие материалы
tools/           служебное
deploy/          эта инструкция
.git/            история
```

### 5. Права на запись

`data/` и `assets/img/uploads/` должны быть доступны на запись (755, иногда 775).
Без этого админка не сохранит ни текст, ни фотографии.

### 6. Заменить .htaccess

Основной `.htaccess` из корня репозитория маршрутизирует запросы на `index.php`.
Файл `deploy/htaccess-static` — только для статики, на PHP-версии он не нужен.

### 7. Завести пароль администратора

Открыть `/admin/` и задать логин с паролем. Пароль длинный, не такой,
как в приложении записи.

### 8. Закрыть служебные каталоги

Проверить, что `https://nlevel.pro/data/content.json` не открывается.
Если хостинг отдаёт файл — написать в поддержку с просьбой закрыть
`/data/`, `/inc/`, `/deploy/`.

## Что осталось сделать в панели

- [ ] **Включить `deflate_module` и `expires_module`** — *Управление веб-сервером
      → Настройки сервера*. Оба выключены, из-за этого нет сжатия и браузерного
      кэша. Это единственное, что заметно влияет на PageSpeed.
- [ ] **Включить «Сжатие данных»** — *Сайты → nlevel.pro → Настройки → Веб-сервер*.
- [ ] **«Кэширование данных» поднять с 0 часов** — *Сайты → nlevel.pro →
      Настройки → Веб-сервер*. Статику здесь отдаёт nginx (`Server: openresty`)
      напрямую, минуя Apache, поэтому `ExpiresByType` из `.htaccess` до картинок
      и стилей не доходит — проверено по заголовкам ответа. Этот переключатель —
      единственный способ включить браузерный кэш для них.
      Ссылки на стили версионные (`style.css?v=918389df`), при правке версия
      меняется, так что долгий кэш безопасен. После включения проверить, что
      HTML по-прежнему отдаётся с `Cache-Control: max-age=0` — иначе правки цен
      посетитель увидит с задержкой.
- [ ] **Залить `.htaccess`** — только после того, как выпущен SSL-сертификат.
      В нём принудительный HTTPS, без сертификата вместо сайта будет ошибка.
- [ ] **Сбросить FTP-пароль** — он засветился в переписке.
- [ ] После запуска — удалить технические синонимы `*.nichost.ru`
      (*Сайты → nlevel.pro → Настройки → Синонимы*). Пока домен не делегирован,
      они нужны для проверки.

Синоним `www.nlevel.pro` **оставить**: он нужен, чтобы редирект на основной
адрес отрабатывал, а не выдавал ошибку.

## Порядок запуска

1. Домен `nlevel.pro` делегируется и начинает резолвиться
2. GlobalSign проверяет домен и выпускает сертификат — раньше шага 1 невозможно
3. Заливается `.htaccess`, сайт переходит на HTTPS
4. Дальше — по `ЧЕК-ЛИСТУ-ЗАПУСКА.md`: Вебмастер, Метрика, РКН
